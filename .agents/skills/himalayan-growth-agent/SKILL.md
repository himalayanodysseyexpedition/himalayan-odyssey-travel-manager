# Himalayan SEO, AEO, GEO & Lead Growth Agent

## Scope and safeguards
Target https://himalayanexpedition.co.in/ and India-wide Himalayan travel demand. Read AGENTS.md, PROJECT_MEMORY.md, the project web-agent skill and the existing seo-audit skill first. Preserve homepage design, mobile/desktop behavior, existing canonical URLs, prices, dates, availability, customer data, hosting and deployment configuration. Free authorized sources only; never spend credits or subscribe without approval. Rank 1 is a target, not a promise.

## Daily intelligence (read-only)
- Read verified Google Search Console, Bing Webmaster Tools and GA4 where authorized. Use final available dates; compare 7/28 days with previous comparable periods and record source, dates, query, page, clicks, impressions, CTR and average position. Distinguish missing data from zero. Use GA4 whatsapp_click as intent, generate_lead as a conversion only when the CRM confirms a saved enquiry; guide_to_booking_click is navigation, not a lead. Report CRM aggregate counts only; never export PII.
- Prioritize Spiti Valley tours, winter Spiti, Kinnaur, Narkanda, Shimla, group/private tours, cabs, hotels and homestays, Chandigarh/Delhi pickup and relevant seasonal 2027 demand. Map one primary intent to one existing canonical page; identify cannibalization, positions 5–20, CTR opportunities and meaningful demand. Avoid keyword stuffing and speculative search-volume numbers.
- Compare actual search results and competing pages with dated evidence. Record market, device and query; distinguish observed SERP from GSC average position. No automated scraping that violates service terms.
- For AEO/GEO, sample repeatable travel questions, document platform, date, query, whether the brand or URL was cited and supporting sources. No universal AI ranking claims. Improve accurate concise answers, itinerary specifics, local expertise, clear sourcing and relevant internal links.
- If a source is unavailable, state the blocker and use only permitted free alternatives or manual exports. Do not silently substitute fabricated metrics.

## Weekly implementation
1. Rank opportunities by observed demand, commercial intent, conversion evidence, effort and risk. Choose a small coherent batch; avoid repeated changes to the same page before enough data accumulates (normally 14–28 days).
2. Inspect existing page/source and actual current facts. Prefer accurate titles/descriptions, headings, descriptive internal links, original useful content, appropriate JSON-LD, image alt text, technical indexing fixes and accessible performance improvements. No bulk thin pages, fake reviews, spam backlinks, doorway pages or hidden text.
3. Create a branch from current main; never push directly to main. Do not change homepage design, canonical/robots indexing policy, customer data or deployment settings. For sensitive changes obtain approval.
4. Run existing static quality checks, compare HTML metadata/canonical/JSON-LD and links, verify no design/booking regressions. Open PR with source evidence, baseline, target URL, hypothesis, exact files, test results and rollback instructions. Merge only after diff review, no conflict and acceptable checks under standing authorization.
5. Verify live deployment independently, then monitor impact after 14/28 days; do not claim causation from correlation or repeatedly request indexing. Revert if evidence shows a material regression.

## Reporting contract
Report dates and source availability, top opportunities, changes and PR links, test/deployment status, follow-up measurement window and genuine enquiry outcomes separately from clicks. Keep private analytics and credentials out of this public repository. Existing scheduled ChatGPT intelligence tasks are external to this skill: this document alone does not start an autonomous process. Never assert scheduling, access, rankings or AI citations without verification.
